# Internationalisation — Visit Imedwan

Implementation: `src/i18n/config.ts`, `src/i18n/index.ts`,
`src/i18n/dictionaries/{en,fr,ar}.ts`, `src/middleware.ts`,
`src/app/[locale]/layout.tsx`.

## 1. Locales and routing

- V1 locales: **`en` (default), `fr`, `ar`** — `locales` array in
  `src/i18n/config.ts`; nothing else is ever served.
- **Path-prefix routing**: every page lives under `/{en|fr|ar}/…`
  (`src/app/[locale]/…`). There is intentionally **no** `src/app/layout.tsx` —
  the `[locale]` layout _is_ the document root (official App Router i18n
  pattern), rendering `<html lang={locale} dir={direction(locale)}>` (see
  `src/app/[locale]/layout.tsx`).
- `src/middleware.ts` redirects `/` and unprefixed paths to the visitor's
  locale using **cookie `vi_locale` → `Accept-Language` (q-value sorted) →
  `en`**, and remembers the choice for a year when a valid locale prefix is
  visited. Unknown prefixes get the locale prepended (they resolve to
  not-found inside the locale) instead of crashing. API routes, Next internals
  and files with extensions are excluded by the matcher.
- Formatting locale tags: `en-MA`, `fr-MA`, `ar-MA` (`intlLocale`).

## 2. RTL

- `isRtl(locale)` / `direction(locale)` — **Arabic is the only RTL locale**
  (`"rtl"`, else `"ltr"`), applied as the document `dir` attribute.
- Arabic is **not** a mirrored copy of an LTR layout: components use logical
  CSS properties (Tailwind logical utilities — `ms-`/`me-`/`ps-`/`pe-`,
  `start`/`end`) so one layout flows correctly in both directions; the header,
  footer and language switcher render from the same markup.
- Fonts: Noto Sans Arabic is bundled (`@fontsource/noto-sans-arabic`) alongside
  Inter/Fraunces so Arabic text uses a proper typeface.

## 3. Dictionaries

- `en.ts` is the canonical dictionary (`as const` — leaves are string literal
  types). `fr.ts` and `ar.ts` are typed `Widen<Dictionary>`: every string leaf
  widens to `string` while the **exact key structure is preserved**, so a
  missing/extra key is a **compile-time error** (`npm run typecheck` enforces
  parity; `tests/unit/i18n.test.ts` double-checks at runtime).
- **27 top-level sections**: `brand`, `common`, `nav`, `home`, `places`,
  `stay`, `guides`, `plan`, `gallery`, `journal`, `search`, `filters`,
  `booking`, `payment`, `account`, `auth`, `provider`, `admin`, `reviews`,
  `wishlist`, `map`, `footer`, `legal`, `errors`, `notifications`, `emails`,
  `misc`.
- `getDictionary(locale)` always resolves a complete dictionary (fallback to
  `en` only for invalid input).
- `t(dictionary, key, vars?)`: walks dotted keys, substitutes `{placeholders}`
  (`replaceAll`), and — important — **returns the key itself when the path is
  missing** (never throws, never an empty string).
- Copy rules (stated in the dictionary headers): destination _facts_ never
  live in dictionaries — they are database content with verification status;
  dictionaries hold interface copy only.

## 4. Brand and slogans (`src/i18n/config.ts`)

- **"Visit Imedwan" is never translated** (asserted by
  `tests/unit/i18n.test.ts`); Arabic brand rendering is `إمدوان`.
- Slogans — one shown per language context, never all at once:
  - en/fr: `Imedwan — Where Water Meets the Mountain` (no official FR slogan
    exists yet — French intentionally falls back to the English one rather
    than inventing copy)
  - ar: `إمدوان — حيث يلتقي الماء بالجبل`
  - Reserved for future Amazigh contexts: Latin-script
    `Imedwan — Aman d Udrar` and Tifinagh `ⵉⵎⴷⵡⴰⵏ — ⴰⵎⴰⵏ ⴷ ⵓⴷⵔⴰⵔ`
    (`sloganAmazighLatin`, `sloganTifinagh` — shown in brand assets, not
    served as a locale).
- Destination naming: `Imedwan` (en/fr), `إمدوان` (ar); per-place names and
  type labels come from `PlaceTranslation` rows (e.g. `أمدا`, `شلال`,
  `حقول وأشجار مثمرة`) — seeded verbatim in `prisma/seed.ts`.

## 5. Translation content models

| Model                    | Unique key                | Fields                                                                       |
| ------------------------ | ------------------------- | ---------------------------------------------------------------------------- |
| `DestinationTranslation` | `(destinationId, locale)` | name, slogan, summary, body, seoTitle, seoDescription                        |
| `PlaceTranslation`       | `(placeId, locale)`       | name, typeLabel, summary, body, seoTitle, seoDescription, verificationStatus |
| `ContentTranslation`     | `(contentId, locale)`     | title, summary (body is Markdown), seoTitle, seoDescription                  |
| `BusinessTranslation`    | `(businessId, locale)`    | name, description, seoTitle, seoDescription                                  |

Read-layer fallback (`pickTranslation` in `src/lib/data/common.ts`):
**requested locale → `en` → any available** — never an empty string.

## 6. Localized SEO

`buildMetadata` (`src/lib/seo/index.ts`) emits:

- one canonical URL per page (`APP_URL + /{locale}{path}`),
- `alternates.languages` hreflang entries for **en, fr, ar + `x-default`**
  (x-default → the `en` variant),
- Open Graph `locale` `en_MA` / `fr_MA` / `ar_MA`, titles/descriptions from
  the localized CMS fields (or dictionary copy), `robots: noindex` when the
  entity sets `noIndex`.

JSON-LD builders emit `inLanguage` for the active locale and include `geo`
blocks **only** when verified coordinates exist.

## 7. Rules (do / don't)

- Do translate around `{placeholders}` — never alter the placeholders
  themselves.
- Don't duplicate strings: email templates, notifications and UI all render
  from the same dictionary (`mail/templates.ts` reads `emails.*`; notification
  types read `notifications.types.*`).
- Don't mirror layouts for Arabic — fix the component with logical CSS
  instead of forking it.
- Don't invent content in translations: FR falls back to EN slogans, unknown
  facts stay `null` in the database and render as pending states.
- Don't serve mixed languages in one context — one slogan/locale per view.
